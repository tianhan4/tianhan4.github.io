通信量、时间模型与演示口径 · Cost model & assumptions

每个 GPU 的输入被等分为 N 块。演示每块 2 个 float32，因此每块 8 字节，单 GPU 的原始数据大小 S = 8N 字节；初始数值只是教学示例。

通信轮数 = 2(N−1)
每 GPU 发送量 = 2(N−1)S/N；接收量相同
T ≈ 2(N−1)α + 2(N−1)S/(Nβ)
  • α 是每轮启动延迟，β 是有效链路带宽（字节/秒）。模型假定块大小相同、各链路可并行，并忽略归约计算和链路争用。发送与接收重叠，因此时间模型不用再乘 2。
  • Reduce-Scatter 第 s 轮（s 从 0 开始），GPU r 发送 C[(r−s) mod N]；结束后 GPU r 持有完整求和块 C[(r+1) mod N]。All-Gather 从这个块开始转发。
  • 右侧保留部分缓冲区用于教学；Reduce-Scatter 完成后，淡化的块属于中间状态，只有标记 ✓ 的块是该 GPU 的有效归约结果。
  • 本演示执行 SUM。若需要 MEAN，可在完成后再除以 N；SUM 不会自动变成均值。All-Gather 只复制完整结果，不能再次相加。
  • 逻辑环不等于物理 GPU 排列。真实实现会切分更小的数据片、流水执行，并可能使用多通道。大消息下带宽项接近 2S/β；小消息或 GPU 数量大时，线性增长的延迟项仍然重要。
